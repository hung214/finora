# 驗收規格：F05 — 支出預算與收入目標

| 項目 | 內容 |
|---|---|
| 對應 BDD | `BDD.md` Feature 5（7 個 Scenario） |
| 對應需求 | SPEC FR-B2~B7（§5.5）、FR-O2（通知開關） |
| 對應驗收場景 | AC-05、AC-13 |
| 里程碑 / 優先級 | M2 / P0 |
| 所需環境 | 任一平台；通知 spy；模擬系統時間（S5.6） |

## 前置條件（每情境開始前重置）

| 資料 | 內容 |
|---|---|
| 預算 | 餐飲 8,000/月、總預算 30,000/月（起始日 1 號） |
| 收入目標 | 60,000/月 |
| 本期支出 | 餐飲已支出 6,500（無預扣） |
| 本月收入 | 已入帳 62,000 |

---

## S5.1 預算 80% 警告僅通知一次（@FR-B4 @AC-05 @P0 @M2）

| # | 操作 | 預期結果 |
|---|---|---|
| 1 | 新增餐飲支出 500（6,500 → 7,000，使用率 87.5%） | 發出通知 N-1（本期第一次） |
| 2 | 檢視總覽 | 餐飲進度條轉為警示色、顯示 87.5% |
| 3 | 再新增 100（7,100，88.75%） | **不**重複發 N-1 |
| 4 | 模擬下期（8/1）後再跨越 80% | 重新允許發一次（每期每級別一次） |

**通過標準**：閾值觸發精準、不重複、跨期重置。
**失敗判定**：每筆都通知（轟炸）＝ **Major**；87.5% 沒觸發 ＝ **Critical**。
**實例走查**：阿花餐飲預算 8,000，月中用到 7,000 收到一次提醒「餐飲預算已用 87%」，之後記帳不會再被這條通知煩，但總覽橫幅持續亮著。

## S5.2 預算 100% 達標與超支通知（@FR-B4 @P0 @M2）

| # | 操作 | 預期結果 |
|---|---|---|
| 1 | 餐飲累計達 8,000（100%） | 發 N-2「預算已用完」 |
| 2 | 再支出 320（8,320，>100%） | 發 N-3「餐飲已超支 320」 |
| 3 | 嘗試繼續記帳 | **不封鎖**（僅警示，記帳流程正常） |

**通過標準**：N-2 與 N-3 各一次；超支金額 = 實際 − 預算，數字正確。
**邊界與例外**：同一筆交易直接從 79% 跳到 105% → N-1、N-2、N-3 依級別依序補發（各一次）。

## S5.3 預算用量包含信用卡預扣（@FR-B5 @P0 @M2）

| # | 操作 | 預期結果 |
|---|---|---|
| 1 | 以信用卡記錄餐飲 1,000（預扣） | 餐飲預算用量 = 7,500（6,500+1,000） |
| 2 | 檢視預算卡 | 標示其中 1,000 為「預扣」樣式/圖示 |
| 3 | 檢視總預算 | 同步計入此 1,000 |

**通過標準**：預算採「承諾支出」口徑（含預扣），且預扣部分可辨識。
**失敗判定**：預扣不計入預算，導致月底帳單來時超支 ＝ **Critical**（違反 FR-B5 設計意圖）。
**實例走查**：阿花刷卡請客 1,000——雖然錢還沒付，預算立刻被吃掉 1,000，她不會月底才發現爆表。

## S5.4 收入目標達成顯示（@FR-B6 @AC-13 @P0 @M2）

| # | 操作 | 預期結果 |
|---|---|---|
| 1 | 開啟總覽頁收入目標卡 | 達標率 103%（62,000/60,000）、顯示「已達成」標記 |
| 2 | 檢視數字 | 已入帳 62,000／目標 60,000 |
| 3 | 檢查通知 | 達成通知 N-10 為 P2 選用——本版不發 |

**通過標準**：達標率 > 100% 顯示正確（非封頂 100% 後失真）；「已達成」狀態明確。
**邊界與例外**：收入目標 0 或未設定 → 目標卡顯示「未設定」引導入口，不顯示 0% 誤導。

## S5.5 本月預計結餘（@FR-B7 @P0 @M2）

| # | 操作 | 預期結果 |
|---|---|---|
| 1 | 開啟總覽頁 | 顯示「本月預計結餘 = 30,000」（= 收入目標 60,000 − 總預算 30,000） |
| 2 | 檢視實際結餘 | = 62,000 − 實際支出（**含預扣**） |
| 3 | 新增預扣支出後複查 | 實際結餘即時減少 |

**通過標準**：「預計」與「實際」兩行並列、口徑清楚（預計=目標 vs 預算；實際=已發生含預扣）。
**失敗判定**：實際結餘漏計預扣 ＝ **Critical**。

## S5.6 自訂預算起始日（@FR-B2 @P0 @M2）

**測試資料**：預算起始日 = 25 號；模擬時間 6 月 3 日。

| # | 操作 | 預期結果 |
|---|---|---|
| 1 | 開啟預算頁 | 週期顯示 5/25 ~ 6/24 |
| 2 | 檢視用量 | 僅統計此期間交易（5/25 前的 5/20 消費不計） |
| 3 | 模擬時間 6/25 | 週期切換為 6/25 ~ 7/24，用量歸零重新累計 |

**通過標準**：跨月週期計算正確；通知計數（N-1/2/3）隨週期重置。
**實例走查**：阿花領薪日 25 號，她把預算週期對齊薪水——每個月 25 號預算重新開始，跟她的錢包節奏一致。

## S5.7 通知可逐類關閉（@FR-O2 @P0 @M2）

| # | 操作 | 預期結果 |
|---|---|---|
| 1 | 設定→通知→關閉「預算警示」 | 開關狀態保存 |
| 2 | 跨越 80%/100% | **不**發系統通知 |
| 3 | 檢視總覽 | 橫幅與進度條警示**仍然顯示** |

**通過標準**：關閉通知只關「推播」，不影響 in-App 視覺警示。
**邊界與例外**：重裝 App 後通知設定隨雲端同步還原（若已連結）。
